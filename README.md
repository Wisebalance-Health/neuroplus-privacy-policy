# 系統維護公告 `system_notify.json` 使用說明

Neuro-Plus+ App 會讀取這個檔案，在**維護時段內**用一個公告視窗蓋住整個 App，使用者看得到公告，但不能操作 App。

- 檔案網址：<https://wisebalance-health.github.io/neuroplus-privacy-policy/system_notify.json>
- 這個檔案放在 GitHub Pages，跟公司後端分開。後端停機維護時，App 還是讀得到它。

---

## 檔案格式

```json
{
  "result": "OK",
  "start_time": "202608130000",
  "end_time": "202608131500",
  "en": {
    "title": "System Maintenance Notice",
    "content": "The system is currently unavailable due to backend update and maintenance operations. Services are expected to resume at 3:00 PM on August 13, 2026. We apologize for any inconvenience caused."
  },
  "zh": {
    "title": "系統維護通知",
    "content": "因系統後台進行更新維護作業，目前暫停使用，預計2026/8/13 下午15:00恢復運作，造成不便敬請見諒。"
  }
}
```

| 欄位 | 說明 |
|---|---|
| `result` | 公告開關。填 `"OK"` 才會生效（大小寫都可以），填其他值（例如 `"OFF"`）就是關閉。 |
| `start_time` | 開始時間，格式 `年月日時分`，一共 12 位數字，例如 `202608130000` 是 2026/08/13 00:00。 |
| `end_time` | 結束時間，格式同上。**到了這個時間公告就消失**，例如 `202608131500` 表示 15:00 整就恢復。 |
| `zh.title` / `zh.content` | 中文標題 / 內文。App 語言是中文時顯示。 |
| `en.title` / `en.content` | 英文標題 / 內文。App 語言是英文時顯示。 |

### 時間規則

- **一律用台灣時間（UTC+8）填寫**。人在國外、手機時區不同的使用者，也會在同一個時刻看到公告。
- 時間是 24 小時制，下午 3 點填 `15`。
- 從 `start_time` 開始顯示，到 `end_time` 停止顯示。
- 時間必須剛好 12 位數字，不能有 `-`、`:` 或空白。

### 什麼情況下公告「不會」出現

公告只會在下面這些條件**全部**成立時出現：

1. `result` 是 `"OK"`
2. `start_time`、`end_time` 兩個都有填，而且格式正確
3. `end_time` 晚於 `start_time`
4. 現在時間介於兩者之間

只要有一項不成立，App 就照常使用，不會被擋住。這是刻意的設計：格式填錯時，App 不會被誤擋。

## 常見操作

### 1. 預告下一次維護（建議做法）

**最好在維護開始前就先把檔案改好並上傳。** App 讀到檔案後會記住時間，時間一到就自動顯示公告，使用者不需要重開 App。

```json
"result": "OK",
"start_time": "202611200100",
"end_time": "202611200400",
```

記得同時更新 `zh`、`en` 內文裡的恢復時間。

### 2. 提早結束維護

下面兩種做法擇一：

- 把 `result` 改成 `"OFF"`
- 把 `end_time` 改成現在或更早的時間

使用者按公告上的「重試」按鈕，或把 App 切到背景再切回來，公告就會消失。

### 3. 延長維護

把 `end_time` 往後改，內文的恢復時間也要一起改。

### 4. 臨時緊急維護

把 `start_time` 填成現在或稍早的時間，`end_time` 填預計恢復的時間，再上傳。

## App 什麼時候會讀取這個檔案

| 時機 | 說明 |
|---|---|
| 打開 App | 每次啟動都會讀取。 |
| App 從背景回到前景 | 會重新讀取（30 秒內重複切換只讀一次）。 |
| 使用者按公告上的「重試」 | 立刻重新讀取。 |
| 到達開始 / 結束時間 | 用最後一次讀到的內容自動顯示或關閉公告，不用重新讀取。 |

另外要注意：

- App 讀取時會略過 GitHub 的快取，所以檔案上傳完、GitHub Pages 部署好（通常 1～2 分鐘）之後，App 就會讀到新內容。可以先用瀏覽器打開上面的網址，確認內容已經更新。
- 如果 App 讀取失敗（例如使用者沒有網路），會沿用上一次讀到的內容；如果從來沒有讀成功過，就不會擋住 App。
- 公告畫面只有「重試」按鈕，**沒有關閉按鈕**，使用者在維護期間無法略過公告。
- 只有已經加入這個功能的 App 版本才會顯示公告，舊版本不會。

## 上傳前檢查清單

- [ ] 用 JSON 檢查工具（例如 <https://jsonlint.com>）確認格式正確，特別注意：
  - 每個欄位之間要有逗號，但最後一個欄位後面**不能**有逗號
  - 引號要用半形的 `"`，不能用全形的 `“ ”`
- [ ] `start_time`、`end_time` 都是 12 位數字，而且用台灣時間
- [ ] `end_time` 晚於 `start_time`
- [ ] 中、英文內文裡寫的恢復時間跟 `end_time` 一致
- [ ] 上傳後用瀏覽器打開網址，確認看到的是新內容
